    1.2Problem statement & actors

    As provided

    Your task is to build a production-ready omnichannel government web application for managing and reporting of Client satisfaction measurement form.

    Story: Clients have no access on the online form; To minimize the printing and manual summary of the reports.

    Project Name: Client Satisfaction Measurement Form Management and Reporting System (CSMF-MRS)

    System Administrator As provided

    "Manages the whole system app." Full access: dashboard, analytics, reports generation, control panel, all CRUD modules.

    Admin As provided

    Separate from System Administrator. Decided An office-scoped administrator (for example, the office's CSM focal person) who sees and reports only on their own office's feedback, and encodes paper forms. See Q4.

    Guest As provided

    "Do not need a login. They will just input their feedback." Sees only the feedback form, on a separate display with no sidebar or navigation.

    How the story is read

    "Clients have no access on the online form" is read as: today there is only a paper form. The system gives clients three channels: a web form reached by QR code at each office counter, an office tablet kiosk (Flutter), and admin encoding of any paper forms still collected. All three feed one database, so the summary report is generated instead of tallied by hand.

    1.10ID strategy Proposed

    The rule: use a UUID where an id is exposed to the public or identifies a person or a record whose count or order is sensitive. Use an auto-increment BIGINT for small, admin-managed lookup tables whose contents are public anyway. Laravel 12's HasUuids generates time-ordered UUIDv7 values, so UUID primary keys still insert in index order and avoid the page splits random UUIDv4 causes.

    TableID typeReason
    usersUUIDv7 As providedSpecified. Also prevents account enumeration through /admin/users/{id}.
    feedbackUUIDv7Created by anonymous guests. Sequential ids would reveal submission volume per office and invite scraping by id.
    kiosk_devicesUUIDv7Token owner; shares the uuidMorphs token table with users.
    offices, services, service_types, regions, sqd_questionsBIGINT auto-incrementPublic lookup data the guest form already lists. Small integer keys make the large feedback and feedback_answers indexes compact. Public URLs use the office slug, not the id.
    roles, permissionsBIGINT auto-incrementAdmin-only and few rows.
    feedback_answers, feedback_issuances, audit_logsBIGINT auto-incrementInternal, high-volume child rows that are never addressed by id from outside.
    role_user, permission_roleComposite primary keyPivot tables need no surrogate id. role_user.user_id is a UUID, as specified.
    feedback.reference_noRandom code CSM-XXXX-XXXXShown to the guest on the thank-you screen. Uses Crockford base32 with no I, L, O or U, so it is easy to read aloud. It is random, so it reveals nothing about volume.

      2.0Decisions awaiting your confirmation

      The specification asks for confirmation before columns are added and wherever something is unclear. Each item has a recommendation, and building waits on the items marked for the earliest sprint.

      2.1Master system directives

      1. API-first, headless. Laravel exposes a versioned JSON API (/api/v1). Nuxt and Flutter are clients only and hold no business rules beyond input hints. Validation, scoring and authorization live in the API.
      2. One source of truth for the form. The guest form is rendered from GET /public/form-definition, so web and kiosk always show identical questions and option text.
      3. Submitted feedback is immutable. No update endpoint exists. Corrections happen by voiding (with reason, user and time) and re-encoding, so every report can be reproduced.
      4. Reports read from the database, never from caches of prior reports. The same filters always produce the same numbers; scoring lives in one tested class (SatisfactionScoreCalculator).
      5. Least privilege. Every admin route checks a permission through a Policy. System Administrator passes through Gate::before. Admin data is scoped to the user's office.
      6. Configuration only through environment. All secrets and hosts are read from each app's .env (src/api/.env, src/web/.env), as in PRJ-itsms. Nothing environment-specific is committed.
      7. Framework conventions first. Use standard Laravel 12, Nuxt 4 and Flutter structures. Services hold use cases. A repository is introduced only for the reporting aggregates, the one place where query logic is complex enough to isolate.
      8. Idempotent everything. Seeders upsert by natural key; migrations are reversible; the public submit endpoint accepts a client_uuid idempotency key so a retried submission never double-counts.
      9. Accessibility is a requirement. The guest form meets WCAG 2.2 AA: labels on every control, 48px targets, keyboard-complete, and no meaning carried by colour or face icon alone.
      10. Small, green commits. Each commit compiles, passes lint and tests, and updates the README or docs when behaviour changes (spec, Development Strategy).

      Request flow: guest submission

      1. Guest scans the counter QR code and opens /f/pho. Nuxt loads /public/offices/pho, /public/offices/pho/services and /public/form-definition.
      2. Nuxt generates a client_uuid (crypto.randomUUID()) when the form opens and keeps it in memory, so a retry after a timeout reuses it.
      3. POST /public/feedback passes the feedback-submit limiter (10 per minute and 50 per day per IP) and the honeypot, then StoreFeedbackRequest validation.
      4. FeedbackSubmissionService opens a transaction. If client_uuid already exists it returns that record (200). Otherwise it writes feedback, nine feedback_answers and a reference number, and returns 201.
      5. The thank-you screen shows the reference number. The kiosk resets to a blank form after 10 seconds.

      Deployment topology Proposed

      In production, one host name (for example csmf.benguet.gov.ph, Q17) serves everything. Nginx serves the statically generated Nuxt build at / and passes /api, /sanctum, /login, /logout, /two-factor-challenge and /user/* to PHP-FPM. Same-origin serving removes CORS from production and lets the session cookie be SameSite=Lax; Secure; HttpOnly. There is no Node process in production, which leaves one less service to patch. In development the web app (csmf-mrs:8030) and API (csmf-mrs:8003) share a host name. Browsers treat different ports on one host as the same site, so Sanctum's stateful cookies work with SESSION_DOMAIN=csmf-mrs.

      2.4War room 4-eyes critique & gap analysis

      Each finding is labelled with its severity and the decision taken, and each panel reviewed the others' areas as the second pair of eyes.

      Principal Software Architect

      • High services has no link to offices or service_types, which makes "per office" reports impossible. Decision: add both foreign keys (Q2, Q7).
      • High Spatie's permission package uses different table and column names (model_has_roles, name) from the spec (role_user, title). Decision: a small in-house RBAC (Gate + Policies + two pivots) that matches the spec exactly.
      • Medium The ARTA questionnaire was revised in 2022 and may change again. Decision: SQD questions are rows (sqd_questions with form_version), and answers are normalized rows, so a new form version needs no schema change.
      • Medium Renaming a service would rewrite historical reports. Decision: snapshot office_name_snapshot and service_name_snapshot on each feedback row.
      • Low Single point of failure: one app server and one DB server. This is acceptable for the load, given documented restore time (RTO 4h, RPO 15 min with binlogs).
      • Low State management: Nuxt uses useState and composables, so no Pinia is needed. Flutter uses Riverpod Notifier/AsyncNotifier per feature.

      Principal DBA & Data Engineer

      • Medium Decided (Q1): follow PRJ-itsms, using the mysql driver to the XAMPP server, which is MariaDB 10.4.32. UUIDs are therefore CHAR(36), never the mariadb driver's native UUID type. JSON columns are stored as validated LONGTEXT there and native JSON on MySQL 8; the schema works on both. Note that MariaDB 10.4 is past its upstream end of life, which matters for the production server choice (Q17).
      • Medium Sizing: about 40 offices × roughly 15 responses a day gives about 150k feedback rows and 1.35M answer rows a year. Composite indexes (office_id, transaction_date) and (service_id, transaction_date) keep a one-office, one-quarter report to an index range scan. Summary tables are deferred until a measured query exceeds 500 ms.
      • Medium Foreign keys from feedback to offices, services, regions and users are RESTRICT, never CASCADE, so deleting master data cannot erase feedback. Offices and services are soft-deleted or deactivated.
      • Medium A plain UNIQUE(code) clashes with soft-deleted rows. Decision: offices and services are never hard-reused; a restored record is undeleted rather than recreated.
      • Low CHECK constraints (enforced by MariaDB 10.2+ and MySQL 8.0.16+) enforce the enum codes and the CC skip rule in the database as well as in PHP.
      • Low GIS review: no spatial data in the requirements, so no POINT or SPATIAL INDEX. Recorded as out of scope rather than added speculatively.

        3.3API conventions

        • Base path /api/v1. A breaking change means /api/v2 running alongside v1 until all clients move (workspace API rule).
        • Success envelope is the Laravel API Resource default: {"data": …}; paginated lists add links and meta.
        • Errors use Laravel's defaults: 422 {"message", "errors": {field: [..]}}; 401, 403, 404, 419 (CSRF) and 429 return {"message"}. The guest UI maps field keys to inline messages.
        • IDs are UUID strings for users, feedback and kiosks, and integers for lookups. Dates are YYYY-MM-DD; timestamps are ISO 8601 with the +08:00 offset.
        • Pagination takes ?page=&per_page= (max 100). Sorting takes ?sort=-transaction_date from a whitelist per endpoint.
        • Auth for the SPA is a Sanctum cookie session (call GET /sanctum/csrf-cookie first; Fortify routes are under /api). Full Sprint 1 contracts: docs/api/README.md. The kiosk sends Authorization: Bearer <token> with the ability kiosk:submit.
        • Throttles are named limiters: public-read (60 per minute per IP), feedback-submit (10 per minute and 50 per day per IP), login (5 per minute per email+IP) and export (10 per minute per user).

namespace App\Enums;

/**
 * ARTA CSM rating bands. Thresholds are fixed by policy, so changing them
 * is a change request with updated tests, not a settings edit.
 */
enum Interpretation: string
{
    case Outstanding = 'Outstanding';
    case VerySatisfactory = 'Very Satisfactory';
    case Satisfactory = 'Satisfactory';
    case Fair = 'Fair';
    case Poor = 'Poor';

    /** @param float $score Percentage already rounded to 2 decimals (0–100). */
    public static function fromScore(float $score): self
    {
        return match (true) {
            $score >= 95.0 => self::Outstanding,
            $score >= 90.0 => self::VerySatisfactory,
            $score >= 80.0 => self::Satisfactory,
            $score >= 60.0 => self::Fair,
            default => self::Poor,
        };
    }

 *   ['1' => int, '2' => int, '3' => int, '4' => int, '5' => int, 'na' => int]
 *
 * Score = (Agree + Strongly Agree) / (Total − N/A) × 100.
 * N/A answers are excluded from the denominator; a tally with no rated
 * answers has no score (null) rather than 0%.
 */
final class SatisfactionScoreCalculator
{
    /** @param array{1:int,2:int,3:int,4:int,5:int,na:int} $tally */
    public function score(array $tally): ?float
    {
        $answered = $this->answered($tally);

        if ($answered === 0) {
            return null;
        }

        return round(($tally[4] + $tally[5]) / $answered * 100, 2, PHP_ROUND_HALF_UP);
    }

    /**
     * Pools several questions (SQD1–SQD8) into one overall score.
     *
     * @param  list<array{1:int,2:int,3:int,4:int,5:int,na:int}>  $tallies
     */
    public function overall(array $tallies): ?float
    {
        $positive = 0;
        $answered = 0;

        foreach ($tallies as $tally) {
            $positive += $tally[4] + $tally[5];
            $answered += $this->answered($tally);
        }

        if ($answered === 0) {
            return null;
        }

        return round($positive / $answered * 100, 2, PHP_ROUND_HALF_UP);
    }

    public function interpret(?float $score): ?Interpretation
    {
        return $score === null ? null : Interpretation::fromScore($score);
    }

    /** @param array{1:int,2:int,3:int,4:int,5:int,na:int} $tally */
    private function answered(array $tally): int
    {
        return $tally[1] + $tally[2] + $tally[3] + $tally[4] + $tally[5];
    }
}

/**
 * Validates a public (web) feedback submission against the ARTA CSM form.
 * The kiosk endpoint extends this request and takes office_id from the device.
 */
class StoreFeedbackRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true; // Public endpoint; abuse is handled by throttling, honeypot and form_token.
    }

    /** @return array<string, mixed> */
    public function rules(): array
    {
        $rules = [
            'client_uuid' => ['nullable', 'uuid'],
            'form_token' => ['required', 'string', 'max:512'],
            'website' => ['prohibited'], // honeypot: hidden field must stay empty
            'office_id' => ['required', 'integer', Rule::exists('offices', 'id')
                ->where('is_active', true)->whereNull('deleted_at')],
            'service_id' => ['required', 'integer', Rule::exists('services', 'id')
                ->where('office_id', $this->integer('office_id'))
                ->where('is_active', true)->whereNull('deleted_at')],
            'transaction_date' => ['required', 'date_format:Y-m-d', 'before_or_equal:today',
                'after_or_equal:'.now()->subDays(30)->toDateString()],
            'client_type' => ['required', Rule::enum(ClientType::class)],
            'sex' => ['nullable', Rule::enum(Sex::class)],
            'age_group' => ['nullable', Rule::enum(AgeGroup::class)],
            'region_id' => ['nullable', 'integer', Rule::exists('regions', 'id')->where('is_active', true)],
            'cc1' => ['required', 'integer', 'between:1,4'],
            'cc2' => ['required', 'integer', 'between:1,5'],
            'cc3' => ['required', 'integer', 'between:1,4'],
            'sqd' => ['required', 'array'],
            'suggestions' => ['nullable', 'string', 'max:2000'],
            'email' => ['nullable', 'email:rfc', 'max:255'],
            'email_consent' => ['exclude_without:email', 'accepted'],
        ];

        foreach (SqdQuestion::activeCodes() as $code) {
            $rules["sqd.{$code}"] = ['present', 'nullable', 'integer', 'between:1,5'];
        }

        return $rules;
    }

    /** @return array<int, callable> */
    public function after(): array
    {
        return [
            function (Validator $validator): void {
                if ((int) $this->input('cc1') === 4) {
                    if ((int) $this->input('cc2') !== 5) {
                        $validator->errors()->add('cc2', 'CC2 must be N/A when you are not aware of a CC.');
                    }
                    if ((int) $this->input('cc3') !== 4) {
                        $validator->errors()->add('cc3', 'CC3 must be N/A when you are not aware of a CC.');
                    }
                }

                $unknown = array_diff(array_keys((array) $this->input('sqd', [])), SqdQuestion::activeCodes());
                if ($unknown !== []) {
                    $validator->errors()->add('sqd', 'Unknown question codes: '.implode(', ', $unknown).'.');
                }

                if (! FormToken::isValid((string) $this->input('form_token'), (int) config('csmf.min_fill_seconds'))) {
                    $validator->errors()->add('form_token', 'The form expired or was submitted too quickly. Please reload and try again.');
                }
            },
        ];
    }
